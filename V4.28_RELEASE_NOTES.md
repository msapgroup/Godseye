# GODSEYE V4.28 — Clean Release Rebuild

V4.28 consolidates the current GODSEYE application into a clean full install/upgrade release instead of carrying forward historical patch artifacts.

## Clean application release

- Server version set to `4.28.0`.
- Fresh installation is performed directly from the extracted release ZIP; no Git clone is required.
- Installer stages an explicit current-file allow-list and cleanly replaces `/opt/godseye`.
- Existing persistent data remains under `/var/lib/godseye` and `/etc/godseye.env`.
- Upgrade creates a pre-upgrade SQLite backup and restores the previous application tree if deployment fails after the swap.
- Application import/migration now sets both working directory and `PYTHONPATH` explicitly.
- Staged ZIP updates reuse the same installer rather than maintaining a second copy of deployment logic.
- Historical root patch/release-note files, obsolete patch scripts, and the legacy endpoint-compiled Windows Agent are removed from the V4.28 package.

## Windows Agent packaging repaired

V4.28 keeps the bundled, already-compiled Windows Agent at independent version `2.2.9`, but repairs the package contract around it:

- Canonical MSI: `GODSEYE-Windows-Agent-x64.msi`
- Canonical guided installer: `GODSEYE-Windows-Agent-x64-Setup.exe`
- Service executable: `GODSEYE.Agent.exe`
- `update-manifest.json` now names the MSI that actually exists in the release.
- MSI and Setup SHA-256 files are regenerated from the bundled binaries.
- Server download/self-update routes and package names now agree.
- The obsolete legacy Agent ZIP/download route is removed.
- Windows build workflow now expects the real `GODSEYE.Agent.exe` assembly name instead of a stale filename.
- Historical v4.23/Agent-2.2.0 artifact names are removed from the workflow.
- Windows CI now validates x64 PE architecture, MSI install/repair/uninstall, LocalSystem automatic service registration, ProgramData state preservation, package hashes, and canonical filenames.

## Future Windows Agent lifecycle

The Windows Agent remains independent from GODSEYE server release numbering. A server update should not require agent reinstall unless an actual agent update is available. Compatible agents use the stable Windows Agent API and can receive hash-verified MSI updates from GODSEYE.

## Release validation

`scripts/validate_release.py` prevents publication/installation when the Windows Agent manifest, filenames, checksums, project version, installer source, server routes, or build workflow disagree.

## Validation boundary

The Linux build environment can validate Python/JavaScript/shell code, package hashes, PE x64 architecture, release structure, and the server test suite. It cannot execute Windows Installer or Windows Service Control Manager. The included Agent 2.2.9 binaries came from the uploaded release; the repaired future workflow is intended to build and smoke-test subsequent Windows Agent packages on `windows-latest`.

## Screenshot pack repaired

Two malformed PNG files from the uploaded tree were repaired/regenerated. V4.28 now validates every packaged screenshot's PNG signature and chunk CRC before installation/publication.

## Installer permission correction

The clean installer preserves execute bits inside `/opt/godseye/.venv` instead of applying a blanket file mode that could make Python/Uvicorn non-executable. The checked-in systemd units are installed directly and remain the single service definition.
